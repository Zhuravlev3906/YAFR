# YAFR — Yet Another File Manager

Локальный организатор файлов для личного использования. Проект создаётся для сортировки файлов по расширениям и пакетного переименования: `1.jpg`, `2.jpg`, `S01E01.mkv`, `S01E02.mkv` и другие имена по шаблону.

Приложение задумано как CLI-инструмент, работающий с локальной файловой системой без сервера. Версия пакета — `0.1.0`, имя Python-пакета и консольной команды — `yafr`.

## Текущее состояние

Реализован слой **Config**:

- Чтение TOML и получение типизированного объекта настроек.
- Проверка типов, неизвестных полей, расширений и шаблонов имён.
- Значения по умолчанию и переопределение отдельных настроек через Python API.
- Поиск пользовательской конфигурации и разрешение относительных путей.
- Единое исключение `ConfigError` для ошибок загрузки и валидации.
- Тесты загрузки, валидации, приоритетов и обработки ошибок.

Команда `yafr` пока выводит `Hello from yafr!`. Парсер CLI, движок сортировки и переименования, просмотр плана и применение файловых операций ещё не реализованы. Настройки этих возможностей уже описаны и проверяются, но сами файлы программа пока не организует.

## Технологии

| Инструмент | Использование |
| --- | --- |
| Python 3.12+ | Язык проекта; `.python-version` выбирает 3.12 |
| `tomllib` | Чтение TOML средствами стандартной библиотеки |
| Pydantic | Модели настроек и строгая валидация |
| platformdirs | Путь к пользовательской конфигурации |
| uv и uv_build | Окружение, зависимости, lock-файл и сборка пакета |
| pytest | Запуск тестов, написанных с использованием `unittest` |
| Ruff | Линтер и форматирование |
| mypy | Статическая проверка типов |

Docker и база данных для текущего проекта не требуются.

## Установка и запуск

Нужны Python 3.12 или новее и установленный `uv`. Команды выполняются из корня проекта.

**Текущая особенность зависимостей:** `service.py` импортирует `platformdirs`, а в `pyproject.toml` сейчас указан только `pydantic`. При этом `uv.lock` ещё содержит `platformdirs`. Перед установкой нужно восстановить декларацию этой зависимости:

```bash
uv add 'platformdirs>=4,<5'
uv sync --locked
uv run yafr
```

`uv add` обновляет зависимости проекта и lock-файл. После этого для обычной установки достаточно `uv sync --locked`; группа `dev` устанавливается по умолчанию.

Ожидаемый результат запуска текущей точки входа:

```text
Hello from yafr!
```

## Архитектура

Проект разделяется на четыре слоя:

| Слой | Ответственность | Состояние |
| --- | --- | --- |
| Config | Чтение, проверка и объединение настроек | Реализован |
| CLI | Команды, аргументы, вывод плана и ошибок | Планируется |
| Engine | Построение и выполнение файловых операций | Планируется |
| App | Связывание слоёв и запуск сценариев | Есть только стартовая функция `main()` |

Текущая структура:

```text
src/yafr/
├── __init__.py              # main(): стартовая заглушка
└── config/
    ├── __init__.py          # Публичный API Config
    ├── loader.py            # Чтение TOML и создание шаблона
    ├── validator.py         # Модели Pydantic и проверки
    └── service.py           # load_config(), приоритеты и ошибки
tests/
├── test_config_service.py
└── test_config_validator.py
pyproject.toml
uv.lock
.python-version
spec.md
README.md
```

Путь загрузки настроек:

```text
load_config()
    → выбор файла
    → ConfigLoader: чтение TOML в словарь
    → проверка файла через Config
    → разрешение путей и объединение переопределений
    → итоговая проверка и возврат Config
```

Слой Config не выводит сообщения и не завершает процесс. Вызывающий код решает, как показать ошибку пользователю.

## Работа с конфигурацией

Основной интерфейс — `load_config()`:

```python
from yafr.config import ConfigError, load_config

try:
    config = load_config("config.toml")
except ConfigError as error:
    print(error)
else:
    print(config.rename.pattern)
    print(config.sort.groups)
```

Сначала сохраните пример ниже в `config.toml` либо создайте шаблон через `ConfigLoader`.

При вызове без аргумента `load_config()` ищет `config.toml` в каталоге, который возвращает `platformdirs.user_config_path("yafr", appauthor=False)`. Файл из текущего рабочего каталога автоматически не подхватывается.

- Если стандартного пользовательского файла нет, используются встроенные значения.
- Если явно указанный файл отсутствует, возникает `ConfigError`.
- Неверный TOML, недоступный файл или некорректные настройки также вызывают `ConfigError`.
- Загрузка через `load_config()` не создаёт файлы или каталоги.

### Пример TOML

```toml
version = 1

[general]
recursive = false
include_hidden = false

[sort]
# Relative to this config file.
# output = "./sorted"
fallback = "other"

[sort.groups]
images = ["jpg", "jpeg", "png", "webp", "heic"]
videos = ["mp4", "mkv", "mov"]
documents = ["pdf", "txt", "docx"]
archives = ["zip", "7z", "tar.gz"]

[rename]
pattern = "{n}"
start = 1
season = 1
```

Все секции и поля можно опускать: недостающие значения заполняются из моделей. Поддерживается версия конфигурации `1`; без поля `version` используется она же.

Встроенные группы расширений совпадают с примером. По умолчанию `sort.output` и `sort.fallback` равны `None`: каталог назначения и резервная группа не заданы. Пример выше и шаблон загрузчика явно включают `fallback = "other"`.

### Переопределение настроек

```python
config = load_config(
    "config.toml",
    overrides={
        "general": {"recursive": False},
        "rename": {"start": 5},
        "sort": {"output": "./sorted"},
    },
)
```

Приоритет: **переопределения → файл → встроенные значения**. Это API для будущего CLI; готовых CLI-флагов сейчас нет.

В `overrides` нужно передавать только явно заданные параметры. Значение `False` переопределяет `True`; отсутствующее поле сохраняет значение файла. `None` не означает «пропустить» и принимается только для допускающих его полей.

Секции объединяются по полям. Таблица `sort.groups` заменяется целиком, без объединения отдельных групп. Исходный словарь переопределений не изменяется. Файл проверяется до объединения: ошибку в нём нельзя скрыть переопределением.

Относительный `sort.output` из файла разрешается относительно каталога конфигурации, из `overrides` — относительно текущего рабочего каталога. Результат — абсолютный путь в виде строки. Также поддерживается `~`. Существование выходного каталога и права записи на этом этапе не проверяются.

### Правила валидации

- Неизвестные поля запрещены на всех уровнях. Типы проверяются строго: строка `"false"` не заменяет `false`, а `true` не принимается вместо целого числа.
- `start` и `season` — целые числа не меньше `1`.
- Расширения указываются без начальной точки и нормализуются без учёта регистра. Повторы внутри группы и между группами запрещены; составные расширения вроде `tar.gz` допустимы.
- Имена групп и `fallback` не могут быть пустыми, равняться `.` или `..`, содержать `/`, `\`, `:` или нулевой символ.
- Шаблоны поддерживают `{n}`, `{season}`, `{episode}` и дополнение нулями, например `{n:03d}` или `S{season:02d}E{episode:02d}`. Максимальная ширина дополнения — 255.
- Обращения к атрибутам и индексам, преобразования вроде `!r`, вложенные форматы и неизвестные поля шаблона запрещены.

Проверки конфликтов с существующими файлами и ограничений конкретной файловой системы относятся к будущему Engine.

### Создание шаблона

Низкоуровневый загрузчик сохраняет возможность создать стандартный файл:

```python
from yafr.config.loader import ConfigLoader

data = ConfigLoader("config.toml").read_config_file()
```

Если файл отсутствует, загрузчик записывает шаблон; существующий файл читает без перезаписи. Родительский каталог должен существовать. Результат — обычный словарь, без валидации Pydantic. Для запрета создания файла используйте `create_missing=False`.

Остальным слоям приложения следует обращаться к `load_config()`, который возвращает проверенный `Config` и объединяет ошибки в `ConfigError`.

## Проверки и сборка

После установки зависимостей:

```bash
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv build
```

Тесты используют временные каталоги и проверяют чтение TOML, значения по умолчанию, валидацию, переопределения, разрешение путей и ошибки доступа. Для форматирования кода используйте `uv run ruff format .`.
